## Important provider finding

The backend explicitly logs `ai_service_running_in_fake_mode` when `OPENAI_API_KEY` is absent. The fake provider is deterministic and useful for development/tests, but it is not equivalent to real AI. A production deployment must configure and verify the intended provider before calling resume extraction, job intelligence, semantic search, matching explanations, or skill-gap output production-grade AI.

## No evidence found

- No hardcoded production credentials or API keys.
- No static dashboard jobs, applications, or match-score arrays in the inspected frontend surfaces.
- No UI copy that silently claims fake provider output is generated by a real model; the server warning is explicit.

## Recommended controls

1. Make provider mode visible in deployment health/observability without exposing secrets.
2. Add a production startup guard if fake AI is not acceptable for the deployment environment.
3. Keep fake-provider tests separate from real-provider smoke tests.
4. Add frontend tests proving dashboard values are rendered from query responses rather than fixtures.
